# Title

0036. 有限な開発実験の着手契約を独立確認の認定契約から分離する

## Status

accepted

## Context

Issue #19/#21/#22の診断を経てもgrossの不確実性と執行上の未検証事項が残る。
`issue20-forward-v1`のB1を新しい開発仮説すべての入口にすると、独立確認が終わるまで
測定改善や利益源泉の検証も進められない。一方、開発の許可を既存方策の収益性認定と
混同したり、確認済み期間を再封印したりしてはならない。

## Decision

[Issue #27開発契約](../research/17-bounded-development-protocol.md)
`issue27-development-v1`を追加し、開発仮説への着手と独立収益性の認定を分ける。
`development_historical`、閲覧可能で確認へ昇格しない`development_shadow`、
別途開始条件と統計設計を満たす`independent_confirmation`を明示する。
今回の開発範囲だけは新契約の予算・停止・分岐表を適用し、独立grossの95%区間が正になる
ことを一律の着手条件にしない。新規学習・候補探索の予算は0とし、次期学習には別の事前契約を要する。

これはADR-0031の証拠分離原則を具体化する追加契約である。旧契約全体やADR-0031/0032を
supersededにはしない。旧#20のB1〜B4と採否表はその凍結確認計画について保持し、
新開発への適用範囲だけを新契約の対応表で置き換える。旧契約の日時・schema・sealed成果物、
#15/#16/#19/#21の判断を変更しない。ADR-0035はproposedのままで、評価器仕様の採用は#28、
公開後quote約定仕様の採用は#31で行う。

## Consequences

- #28〜#32は有限な予算と引渡し条件で進行でき、外部source未決で全historical開発を止めない。
- 開発上の検討余地、確認済み収益性、実口座導入は別判断となる。今回は後二者を許可しない。
- 費用削減によるnet改善はgross低下との分解で検討できるが、結果に合わせたサイズ調整は許可しない。
- 変更した仮説・測定は別IDと実行前登録を必要とし、旧確認の成績救済や無制限探索に使えない。
- 子Issueの実験・観測完了はIssue #27自身の完了条件ではない。
