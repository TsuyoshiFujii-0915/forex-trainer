# 0009. 残差行動スキーム(ルールをベースとする residual RL)

## Status

accepted

## Context

signed 会計の下でクロスセクション・リバーサル・ルール(top2、サイズ0.8)は walk-forward
2019〜2025 でネット +7.0%/年・Sharpe 0.93 を達成する一方、素の PPO(ens3)は +3.1%/年・
Sharpe 0.35 に留まり、レジーム逆風年に大きく崩れる。リスクオーバーレイ(ボラ目標・
ドローダウン制御)はリターンを増やさないことを因果的な事後検証で確認した。エージェントに
ルール成績を構造的な下限として与え、学習は「ルールからの逸脱が改善になる場合」に限定する
residual RL が標準的な解決策である。

## Decision

`run.residual` を必須キーとして追加する(`"none"` またはマッピング)。マッピング時:

- `feature`: ベースルールが参照する特徴量名(`env.features.selected` に含まれること)
- `top_k`: ランク端のスロット数
- `base_size`: ベースの重み(低い値のペアに +base_size、高い値のペアに −base_size —
  リバーサル方向で固定。モメンタム方向が必要なら特徴量の符号を反転して登録する)
- `scale`: エージェント残差の半径

トレーナー側の Gymnasium ラッパーが毎決定で最新バーの当該特徴量からベース重みを計算し、
最終重み = `clip(base + scale × agent_action, −1, 1)` を環境に転送する。学習・検証・評価の
全環境に同一に適用する。PPO の初期方策は平均ゼロ付近から始まるため、学習初期の挙動は
ベースルールにほぼ一致する(構造的な下限)。

## Consequences

- エージェントの成績下限がルール(+7.0%/年)になり、学習の失敗が「ルール比の劣化」として
  即座に可視化される
- エージェントが学習できるのは残差の範囲(±scale)に限られる — 意図した制約
- ベースルールの形(top-k リバーサル)を config で固定するため、ルール自体の探索は
  引き続き ceiling 診断側の責務
- 全 config に `residual` キーの追記が必要
