## 1. 目的と現在地(サマリ)

**目的**: 現実的な取引戦略(取引しない縮退の禁止)で、コスト控除後に有意なプラスを出す
RL エージェントの構築。目標値はユーザー設定で **walk-forward ネット +7%/年**、かつ
「2019〜2025 への期間適合ではなく、包括的に勝てるルール」であること。

**現在地(2026-07-20)**:

- **最も頑健な発見はルールレベル**: 価格クロスセクション・リバーサル(ノーフィッティング)
  が、**構造的に独立した2つのユニバース(JPY建て・USD建て)× 2つの時代
  (2009〜18・2019〜25)すべてで正**。JPY +3.1%/年(4/10, 5/7)、USD +4.2%/年(5/10, 5/7)。
  方向を反転させたモメンタムは両ユニバース・両時代で明確に負
- **純RLはユニバース間で汎化しない**: JPYでは +4.7%/年(両時代正)を出すが、
  同じレシピをUSDに適用すると **−2.9%/年に失敗**(era1 −6.6%)。ルール単体は
  USDでも正なので、これは「学習の失敗」であって「タスクが解けない」わけではない
- **残差RL(ルール床+RL)の効果はユニバース依存**: JPYではルール単体を上回る
  (+4.4% vs +3.1%)が、USDではルール単体を**下回る**(+3.1% vs +4.2%)。
  「RLが一貫してルールを改善する」とは言えない
- 目標 **+7%/年は未達**。一時「達成」と報告した構成(ラウンド14, +7.13%/年)は、
  ベースルールが2019〜2025への期間適合だったため撤回済み(→ §6)

## 2. リポジトリ構成

隣接2リポジトリ(trainer→env の一方向依存、trainer ADR-0001):

- **forex-env-v3**: 検証済みの Gymnasium 環境(マルチペア、目標配分リバランス会計、
  log資産リターン報酬)。**基軸通貨は任意**(ADR-0010、旧JPY限定を解除)。ADR 0001〜0018。
  テストスイートで継続検証
- **forex-trainer**(本リポジトリ): 実験ハーネス。1 YAML = 1実験
  (アルゴリズム×ネットワーク×特徴量 + 決定間隔・残差スキーム)。ADR 0001〜0010。
  テスト 100件超

アンサンブル評価)/ `forex-fetch-dukascopy`(長期時間足取得)/ `forex-add-carry`

PPP・グローバル系列付与)/ `forex-env-fetch`(env側、yfinance/synthetic)

## 4. 実験プロトコル(必ず守ること)

1. **二時代 walk-forward**: 開発フォールドは評価年 2009〜2025 の17本
   (expanding train、val 直前6ヶ月)。合格には **2009〜18 と 2019〜25 の両バケットで
   ネット正**が必要。configs 例: `configs/wf_r16_long_full/`(JPY純RL)、
   `configs/wf_r18_usd_longf/`(USD純RL)、`configs/wf_r19_{jpy,usd}_res/`(残差RL)
2. **独立ユニバースでの再現を要求する**: 1ユニバースだけで両時代正でも「汎化」とは
   認めない。**JPY建てとUSD建ての両方**で確認して初めて頑健とみなす(§1参照)
3. **封印期間**: 2007〜2008 は最終設計の一発確認専用(使用済み1回)。2026H1以降は
   前向き検証に充てる
4. **RL の前に ceiling 診断**: 新しい特徴量/ユニバースでは、まずスクリプト化した
   ルールを env のコストモデルに通してグロスが正であることを両時代で確認する
   (グロス≈0や片時代のみ正の空間にはRLを投入しない)。パターンは research/03・06 と
   scratchpad の `*_ceiling*.py`
5. **多シード+アンサンブル**: 判定は3シード以上。行動平均アンサンブルは **N=3 が最適**
   (5以上は合意部分しか残らず痩せる)
6. **グロス/ネット分解**: metrics.json の `gross_cumulative_log_return` で
  「シグナル欠如」と「コスト負け」を常に区別する
7. **検証成績を信用しすぎない**: 検証→評価の相関は実測で**負**(−0.3前後)。
   検証はチェックポイント選択のみに使い、構成選択やゲーティングには使わない
8. **新しい価格データは必ずスパイク監査**してから使う(§6参照)

## 6. 確定した知見と教訓

**効いたもの(頑健)**:
- クロスセクション・リバーサルという**ルールクラス自体**(2ユニバース×2時代で検証済み。
  現時点で唯一「包括的」と呼べる発見)
- 符号付き資金調達(旧・対称オーバーナイト課金は戦略を年約2.7%過小評価していた)
- ロールアウト長 n_steps 256→1024 + 300k steps(JPY純RLの最大の単一改善)
- クロスセクショナル特徴量(`xz_mom24`/`xr_mom24`)

**効かなかったもの / ユニバース依存だったもの**:
- **純RLのユニバース間汎化**(JPYで良好・USDで失敗。R18の最重要な負の結果)
- **残差RLの一貫した優位性**(JPYで改善・USDで悪化。R19)
- 新規外部ファクター(10年金利差・PPP)単体、VIX条件付けエクスポージャー抑制
- ペア間attention(xattention)、RecurrentPPO、TQC(無取引に縮退)、正則化PPO
- 決定間隔 k>1 は RL には有害(ルールには有効)
- ハードなレバレッジ上限、自己ボラ・ターゲティング、ドローダウン制御オーバーレイ

**最大の教訓(撤回事件)**:
- 同じ検証フォールドに設計反復を重ねると、コードが正しくても**研究プロセス自体が
  in-sample 選択**になる。対策は二時代基準 + **独立ユニバースでの再現要求**
  (1ユニバースだけの両時代正では不十分というのが今回の追加教訓)
- **価格データは必ずスパイク監査**: yfinance 旧データに「±数百%→翌日全戻し」の不良
  プリント(NOKJPY ±460%、USD/EUR・USD/NOK等)。リバーサル系は不良ティックを偽の
  利益として刈り取る。本物の歴史的イベント(2015年SNBのCHF固定撤廃)は修復
  アルゴリズムが正しく「非可逆」と判定し保持することを確認済み。修復ロジックは
  scratchpad 参照(検出条件: |return[i]|>8% かつ符号反転かつ |return[i+1]|>0.6×|return[i]|)
- **RLの「学習成功」は割り引いて評価する**: 1ユニバースでの正の結果だけでは
  「汎化した技能を学習した」証拠にならない。必ず独立ユニバースで再検証すること

## 7. 運用上の落とし穴

- **Dukascopy datafeed は激しくスロットリング**(数時間〜日単位の IP ブロック実績)。
  `forex-fetch-dukascopy` はリクエスト間隔・リトライ実装済みだが、並列取得は厳禁
- **学習バッチ実行中にソースを編集しない**(editable install のため実行中バッチが
  不整合なコードを import して落ちる。実際に11 run 損失した実績あり)
- **ruff --fix の自動整形との競合**: 同一ファイルへの連続 Edit の間に lint hook が
  「未使用」と誤判定してimportを削除することがある(2つ目の使用箇所の追加が
  1つ目のimport追加と別editになっていると起きやすい)。エラーが出たら該当箇所を
  Read し直して再適用する
- 日足評価は **warmup(32)+窓(31)で評価区間の先頭63バーが消える**(半年指定なら
  実質1四半期)。フォールド間では一貫しているので比較は有効
- `normalize: true`(観測窓内z-score)は低速特徴量とペア間水準比較を破壊する。
  クロスセクション課題では `false` + スケールの揃った特徴量を使う(residual 使用時は
  config が強制)
- 環境の基軸通貨は `currency_pairs` の全要素で統一する必要がある(env ADR-0010、
  混在は ConfigError)。1つの env インスタンスで複数基軸通貨は扱えない
  (別ユニバース=別環境インスタンスとして学習する)

## 8. 推奨する次の一手(優先順)

1. **なぜUSDで純RL/残差RLが崩れるかの原因分析**: JPYとの構造的な違い
   (レバレッジ・コスト・特徴量分布)を比較し、USD側だけ悪化する具体的なメカニズムを
   特定する。ここが解明されない限り「汎化するRL」は作れない
2. **3つ目の独立ユニバース**での追試(例: EUR建て、GBP建て)。2ユニバースでは
   「たまたま2つとも似た挙動」の可能性を排除できない
3. **マルチユニバース同時学習**: 複数の基軸通貨ユニバースを跨いだ特徴量正規化・
   同時学習で、ユニバース非依存な方策を学習できないか検証する
4. **CFTC建玉データ**: 6/9ペアのみカバーだが、ポジショニング系という未検証の
   情報源。ceiling診断から着手
5. サイズアップは Sharpe/汎化性が確認できるまで**非推奨**

## 9. 再現手順(ルールベンチマーク — 現時点で最も信頼できる成果物)

```bash
# JPYユニバース: 既存キャッシュ data/jpy_9pairs_1d_factors.parquet を使用
# USDユニバース: 既存キャッシュ data/usd_9pairs_1d_factors.parquet を使用
# (どちらも forex-add-carry → forex-add-factors の連鎖で再構築可能。§3参照)

# ルールの ceiling 診断(学習不要、数分):
# scratchpad の ceiling_factors.py パターンを参照
# (walk_eval_range + build_single_env にスクリプト化ルールを差すだけ)

# RL(残差スキーム、現状最良のRL構成)の1フォールド再現:
for s in 1 2 3; do
  uv run forex-train --config configs/wf_r19_jpy_res/wf2024_r19_jpy_res.yaml --seed $s
done
uv run forex-ensemble-eval --runs runs/wf2024_r19_jpy_res/* --runs-root runs
```

全17フォールドのバッチ実行例は research/05・06 各所のシェルスクリプトパターンを参照
(学習→評価→ens3→時代バケット集計)。
